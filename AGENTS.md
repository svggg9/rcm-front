# Рабочий контекст рцмаркет / frontend

## Начало работы

- Общайся с пользователем по-русски. Основное рабочее место — Windows; команды запуска документируй для PowerShell, используя относительные пути.
- В начале задачи прочитай README.md, PROJECT_PLAN.md и WINDOWS_HANDOFF.md. Для UI прочитай актуальный верхний раздел DESIGN_SYSTEM.md; для выкладки — DEPLOYMENT_2026-09-19.md.
- Проверь git status и текущую ветку, сохрани существующие пользовательские изменения. Основная ветка этого репозитория — main; backend svggg9/rcm использует master.
- Найди соседний backend по доступным каталогам, не полагайся на /Users/admin/... и не предполагай, что он уже клонирован. Если задача затрагивает API, прочитай его BACKEND_PLAN.md и соответствующий код.
- Текущие инструкции пользователя имеют приоритет над историческими документами. Старые fix/* ветки и архивные планы не сливай и не применяй автоматически.

## Состояние и ближайшая работа

- Релиз 19 сентября 2026 выложен на test и production, обе БД — V99. Полные SHA и проверки находятся в DEPLOYMENT_2026-09-19.md. Не начинай обычную задачу с повторной выкладки или нового полного аудита.
- Сначала восстанови локальный запуск, затем работай по PROJECT_PLAN.md. При переносе не переписывай работающие модули и не меняй зависимости без причины.
- Восстановление пароля реализовано; email OTP login всё ещё требует согласования с backend. Кнопка отмены заказа не доказывает готовность backend-отмены неоплаченного заказа.

## Правила интерфейса

- Сохраняй Inter, чёрный/белый/золото, общие компоненты app/components/ui и токены app/styles.
- У продавца отдельная шапка и два ряда навигации без счётчиков. Верхний раздел «Каталог», кнопки добавления возле поиска и фильтров.
- Товар редактируется в правой панели поверх списка; прямой URL остаётся рабочим. Подборка — компактный диалог, мобильный редактор — полноэкранный. Сохраняй предупреждение о несохранённых правках.
- Не возвращай ранние варианты из исторических секций DESIGN_SYSTEM.md. Демонстрационные страницы не являются новым разрешением менять весь интерфейс.
- Не меняй бизнес-статусы/доступные действия только по оформлению UI; сверяй API-контракт. Поиск заказов сейчас работает по загруженной части списка.

## Запуск и проверки

- Node 24.x; npm ci, npm run dev. Локальный frontend http://localhost:3000, backend http://localhost:9696. См. .env.example и README.md.
- Для изменения кода запускай соразмерные проверки: npm run lint, npx tsc --noEmit; npm run build при изменениях маршрутов/сборки или перед релизом. Для правок только документации достаточно проверки ссылок и git diff --check.
- Для редактора учитывай прямой URL, refresh/back, сохранение, dirty-close, вложенные диалоги и ширины 320/390/1280.
- Не объявляй полный E2E пройденным по сборке или smoke. В отчёте указывай фактически выполненные проверки.

## Данные и передача результата

- Env и локальная БД не переносятся через Git. Не печатай и не коммить секреты; NEXT_PUBLIC_* доступны браузеру.
- docs/mac-artifacts-2026-09 — исторический архив с Mac-путями. Не выполняй повторно import.sql/upload-images.cjs для подготовки Windows. Работа со старым общим S3 не входит в обычную UI-проверку.
- Продолжай в рамках текущего запроса. Разрешение на прошлый релиз не означает необходимость выкладывать каждую следующую правку.
- После изменения статуса задачи актуализируй PROJECT_PLAN.md; при изменении запуска — README/WINDOWS_HANDOFF. Различай «реализовано», «проверено», «выложено» и исправляй устаревшие утверждения, а не только добавляй оговорку сверху.
