# Простой frontend восстановления пароля

7 сентября 2026: реализован локально, без выкладки. Тесты, lint, typecheck,
сборка и браузерный прогон в этой задаче не запускались по договорённости.
Посторонние изменения frontend не входят в эту задачу.

## Вход в сценарий

- «Забыли пароль?» в AuthModal и на `/auth/login` открывает `/auth/password/reset`.
- Email → код из письма + новый пароль и подтверждение → сообщение об успехе.
- «У меня уже есть код» позволяет продолжить после обновления страницы без
  нового запроса письма. «Изменить почту» возвращает к первому шагу.
- После успеха пользователь входит обычным способом. Безопасный `next`
  сохраняется при переходах; email, код и пароль не добавляются в URL или storage.

## Backend-контракт

- `POST /api/auth/email/password-reset/start`, JSON `{email}` → `202` с
  `ttlSeconds` и `resendAfterSeconds` (600 и 60 по текущему контракту).
- `POST /api/auth/email/password-reset/complete`, JSON `{email, code, newPassword}`
  → `204`; backend очищает auth cookie и отзывает прежние сессии.
- Старый несуществующий `/api/auth/password/reset/complete` и token из query
  больше не используются. Нужен backend с коммитом `68fc98d` из `rcm/master`.
  Тестовый сервер с релизом от 4 сентября нового API ещё не содержит.

Ответ о принятии запроса не подтверждает наличие аккаунта или доставку письма.
Восстановление доступно только для единственного аккаунта с ранее подтверждённой
почтой. Для аккаунтов Яндекса остаётся предложение войти через Яндекс ID.

## Поведение формы

Код — строка из 6 цифр с сохранением ведущих нулей. Пароль не обрезается и
не нормализуется: минимум 8 символов, не только пробелы, максимум 72 байта UTF-8;
оба поля должны совпадать. Запросы не повторяются автоматически.

Повторная отправка имеет обратный отсчёт по ответу backend; 429 показывает
предупреждение о лимитах. Клиентский таймер — подсказка, окончательные лимиты
обеспечивает Redis. Ошибки API переводятся в понятные сообщения без вывода сырого
ответа сервера. При потере ответа complete сообщается, что пароль уже мог измениться.

После успеха очищается только указатель на авторизованную корзину и обновляются
потребители состояния авторизации; гостевая корзина и избранное не удаляются.
Поля и кнопки используют существующие компоненты, оформление минимальное.

## Отложенная общая проверка

Проверить оба входа в сценарий, реальное SMTP-письмо, leading-zero код, resend и
истечение кода, 5 ошибок, 429/503/недоступную сеть, совпадение паролей и границу
72 байт, отказ старому паролю/JWT, обычный вход после успеха, безопасный `next`,
обновление страницы, управление с клавиатуры и мобильную верстку.
