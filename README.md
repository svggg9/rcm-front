## Запуск на Windows / PowerShell

Используй Node.js 24.x и npm: эта версия использована для серверных frontend-сборок 19 сентября. Зависимости устанавливаются по package-lock.json.

```powershell
npm ci
if (!(Test-Path .env.local)) { Copy-Item .env.example .env.local }
npm run dev
```

Открыть [localhost:3000](http://localhost:3000). Для данных нужен запущенный backend на порту 9696; его запуск описан в README backend. Без него интерфейс не является полностью рабочим marketplace.

`.env.example` содержит только локальные URL. `NEXT_PUBLIC_API_URL` используется браузером и встраивается при сборке; `SERVER_API_URL` — серверной частью Next.js. Нельзя помещать секреты в `NEXT_PUBLIC_*`. При изменении public URL для релиза нужна новая сборка. Карта ПВЗ дополнительно использует public Yandex Maps/Suggest keys — настраивай только для соответствующего сценария.

Локальные `.env.local`, node_modules и .next в Git не входят. Не перезаписывай существующий env и не обновляй зависимости просто ради переноса.

Для фотографий из локального MinIO добавь в `.env.local`:

```dotenv
RCM_LOCAL_CATALOG_IMAGES=true
```

Затем перезапусти `npm run dev`: одного обновления env в работающем Next недостаточно для пересчёта настроек `images`. В dev разрешён адрес `http://127.0.0.1:9000/rcm-windows-local` для `catalog-v1/`, `products/`, `brands/`, `storefront/` без query. Файл также должен быть доступен на чтение в MinIO; 403 от хранилища проверяется отдельно от ошибки `next/image`. Проверка конфигурации: `node scripts/check-local-storage-config.mjs`.

### Локальная проверка seller-навигации

`node scripts/check-seller-navigation.cjs` запускает собственный mock-API на 19640 и Next dev на 13040. Рабочую БД/S3 не использует. Нужны Playwright и установленный Microsoft Edge; если Playwright находится вне проекта, задайте `$env:PLAYWRIGHT_PATH` абсолютным путём к его пакету. Тестовый Next использует `build/navigation-check`, чтобы не конфликтовать с обычным dev/build; стандартный запуск остаётся в `.next`. Оба тестовых процесса закрываются по завершении. Проверяются панели заказов/возвратов, история, черновик проверки и мобильные ширины. Это не проверка реальных платежей/доставки.

Индикаторы открытых задач проверяются отдельно с теми же требованиями к Playwright/Edge:

```powershell
node scripts/check-seller-navigation-attention.cjs
```

Runner использует mock API/Next на 19643/13043 и `build/navigation-attention-check`. Проверяет круглые точки без слов, точные счётчики и 99+, прямые переходы, следующую страницу возвратов, обновление после решения, частичную ошибку API и отмену устаревшей загрузки. Мобильные ширины и чёрные подписи проверяются на 320/390/1280; screenshots — `build/navigation-attention-screenshots`. Рабочая БД/S3 не используются, процессы закрываются после проверки.
