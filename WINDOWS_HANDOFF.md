# Продолжение рцмаркет на Windows

Состояние передачи: 19 сентября 2026. Основная работа переносится на Windows.

## Репозитории

- Frontend: https://github.com/svggg9/rcm-front — ветка `main`.
- Backend: https://github.com/svggg9/rcm — ветка `master`.
- `notification-gateway` находится внутри backend, отдельное клонирование не нужно.
- Старые `fix/*` ветки сохраняются как есть. Нельзя считать их слитыми только по названию коммитов.

Открой на Windows общую родительскую папку с обоими репозиториями. Для нового рабочего каталога, PowerShell:

```powershell
git clone --branch main git@github.com:svggg9/rcm-front.git
git clone --branch master git@github.com:svggg9/rcm.git
```

Если копии уже есть, сначала `git status` в каждой; не стирай локальные изменения. В чистых копиях переключись на соответствующую ветку и выполни `git pull --ff-only`. При расхождении историй сначала разберись с ним, без reset/force push. Используй GitHub HTTPS вместо SSH, если на Windows настроена именно HTTPS-авторизация.

## Окружение и запуск

Нужны Git, Node.js/npm, JDK 21, PostgreSQL и Redis. Для integrationTest — Docker с Linux-контейнерами. Gradle поставляется wrapper-ом. Для gateway в package.json требуется Node 24.x; его запуск нужен только для сценариев gateway. Версии npm-зависимостей восстановить через lock-файл, не обновлять при переносе.

Frontend, из `rcm-front`:

```powershell
npm ci
# Создать .env.local с локальными адресами, если файла ещё нет:
# NEXT_PUBLIC_API_URL=http://localhost:9696
# SERVER_API_URL=http://localhost:9696
# NEXT_PUBLIC_SITE_URL=http://localhost:3000
npm run dev
```

Backend, из `rcm`:

```powershell
# Только если локального .env ещё нет:
if (!(Test-Path .env)) { Copy-Item .env.example .env }
# Заполнить .env согласно пояснениям ниже до запуска.
.\gradlew.bat bootRun
```

Для Windows удобен `SPRING_PROFILES_ACTIVE=dev`: отслеживаемый application-dev.yml читает подключение PostgreSQL/Redis из env. Локальный Mac application-local.yml в Git отсутствует. Gradle bootRun сам читает корневой .env; запуск JAR/через IDE требует отдельного подключения переменных.

В .env задать SERVER_PORT=9696, адрес/пользователя/пароль **локальной** PostgreSQL, Redis, свой JWT_SECRET (минимум 32 случайных байта). Проверить порт БД: в примере 25432, на Mac использовался 25433; Windows должен использовать реально созданный локальный порт.

Для начального изолированного запуска выставить PAYMENT_PROVIDER=MOCK, AUTH_EMAIL_PROVIDER=mock, CDEK_DELIVERY_ENABLED=false, CDEK_DELIVERY_MOCK_MODE=true, TELEGRAM_ENABLED=false, YANDEX_DELIVERY_ENABLED=false. Значения .env.example по умолчанию включают внешние интеграции — не копировать их без проверки. Использовать отдельное локальное/test S3-хранилище; не выполнять upload/delete в общем bucket `rcm`. S3-конфигурация нужна для соответствующих операций, фиктивные ключи их работоспособность не обеспечивают. Реальные OAuth/SMTP/TBank/CDEK настраиваются и проверяются отдельным этапом.

Flyway содержит миграции до V99. Запуск приложения может применить их к выбранной базе: убедиться, что это локальная изолированная БД. Данные текущей Mac-БД, учётные записи и загруженные медиа Git не переносит. Если нужны ровно те же товары/пользователи — потребуется отдельный приватный перенос БД и файлов либо подготовка новых тестовых данных.

## Готовый промпт для новой задачи

Продолжаем проект рцмаркет на Windows как основном рабочем месте. Репозитории: svggg9/rcm-front (main) и svggg9/rcm (master); notification-gateway внутри backend. Забери актуальные изменения через fetch/pull --ff-only, предварительно проверь локальные правки. Не делай reset/force push и не сливай старые fix-ветки автоматически.

Прочитай WINDOWS_HANDOFF.md, frontend PROJECT_PLAN.md и DESIGN_SYSTEM.md, backend BACKEND_PLAN.md и документы password reset. Они актуализированы 19 сентября 2026. Сначала настрой Windows-окружение и запусти локально обе части, сохраняя существующие конфиги и используя изолированные БД/Redis/S3 и mock-интеграции. Если не хватает реальных параметров или данных, запроси только недостающую информацию; секреты не выводи и не коммить.

Сохрани последние решения: Inter, чёрный/белый/золото, отдельная шапка продавца, двухуровневая навигация без счётчиков, верхний раздел «Каталог», действия добавления у фильтров, товар в правой панели поверх списка, подборка в компактном диалоге, защита несохранённых изменений и мобильный полноэкранный редактор. Продолжай текущую реализацию, не переделывай дизайн заново.

Первый рабочий блок после запуска — сверка seller-навигации, списка товаров/подборок, сортировки/пагинации, массовых действий и редактора (прямой URL, refresh/back, сохранение, dirty-close, мобильные 320/390 и desktop 1280). Исправляй подтверждённые дефекты. Затем двигайся по актуальному плану: B1/B2 неоплаченные заказы/резервы и жизненный цикл, B3 расхождение email OTP, далее интеграции/наблюдаемость. TTL и правила поздней оплаты согласуй до реализации. Не выдавай frontend-кнопку отмены за готовую backend-отмену неоплаченного заказа.

Полный backend/build/E2E-прогон был отложен до завершения frontend; не начинай с массовой проверки интеграций и серверной выкладки. Проверяй текущие изменения соразмерно; публикация кода на GitHub не означает разрешения на deployment, реальную оплату, отправку уведомлений или повторный импорт demo-товаров. В конце каждого законченного блока обновляй план и явно различай «реализовано», «проверено», «выложено».
